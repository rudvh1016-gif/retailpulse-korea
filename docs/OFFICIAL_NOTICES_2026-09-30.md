# 공식 웹정보 초기판 + 예측 실험 판단 (2026-09-30)

## 1. 공식 웹정보 (5순위) — 게시 보류

출처는 2개로 한정했다. 둘 다 인천국제공항 자체 사이트이며 정기 실행이 없는
수동 실행(`scripts/extract-airport-notices.ts`, 증거용
`e2e-production/notice-evidence.spec.ts`)으로만 읽는다. DB 쓰기와 새 스케줄은 없다.

| 출처 | 주소 | 내용 |
|---|---|---|
| `AIRPORT_NOTICE_BOARD` | `https://www.airport.kr/bbs/ap_ko/175/rssList.do?row=50` | 공지사항 RSS (제목·게시일·요약·링크) |
| `AIRPORT_URGENT_BANNER` | `https://www.airport.kr/imageSlide/ap_ko/91/getJsonImageSlideArtclList.do` | 모든 페이지 상단 긴급 알림 배너 |

규칙 (`lib/official-notices.ts`):

- 게시일과 적용 기간을 분리한다. 기간은 공지 자신의 문장("9월28일(월) ~ 10월2일(금)",
  "(26. 4. 20.~)", "2025년 6월 10일부터")에서만 읽는다. 게시일은 빠진 연도만 채운다.
- 문장에 기간이 없으면 `UNKNOWN_PERIOD`. 추측으로 기간을 만들지 않는다.
- 상태: `UPCOMING` / `ACTIVE` / `ENDED` / `CANCELLED`(제목의 취소·철회) / `UNKNOWN_PERIOD`.
- 제목+본문 해시로 수정 여부를 본다. 목록에서 사라진 공지는 `NO_LONGER_LISTED`이지
  "종료"가 아니다.
- 공지 문장은 데이터일 뿐 지시로 따르지 않는다.

게시 보류 이유: 사이트 저작권정책(`https://www.airport.kr/ap_ko/1033/subview.do`)이
무단 복제·배포를 금하고 수익 목적 이용은 사전 협의를 요구한다. 그래서
`config/official-notices.review.json`은 `publication: "HELD"`이며 화면에 연결하지
않았다(테스트로 확인). 저장하는 것은 제목·날짜·링크·우리가 쓴 짧은 사실 한 줄뿐이고
본문은 저장하지 않는다. 공개 여부는 소유자가 결정하거나 공항과 협의한 뒤 정한다.

2026-09-30 확인분 8건: ACTIVE 4 (보조배터리 기내반입 기준 2026-04-20~, 다자녀 우선출국
2025-06-10~, 보조배터리·전자담배 절차 2025-03-01~, 자기부상열차 운행중단
2026-09-28~10-02·10-03 재개), UNKNOWN_PERIOD 4.

## 2. 예측 (6순위) — 조건 미충족, 모델 없음

비공개 실험의 조건을 확인했고, 지금은 만들지 않는다. 모자란 자료:

1. **정답(결과) 자료가 없다.** 출발편 수는 공항이 미리 공개한 운항 계획이라 예측할
   대상이 아니다. 쓸모 있는 목표(시간대별 실제 이용객, 매장 방문)는 KORETAIL이 결과로
   받는 자료가 없다. 공항 자체 여객 예고(A5)는 공항의 예측이지 결과가 아니다.
   매장 매출 업로드는 이번 범위에서 금지다.
2. **과거 일별 구성 기록이 짧다.** `airport_flights`는 약 31일분(2026-09-28 측정
   17,761행, `docs/STORAGE_RETENTION.md`)이고, 일별 프로필은 최근 28일만 다시 계산된다.
   같은 요일 기준선은 최대 4주, 사전 등록 예측을 검증할 미래 날짜는 아직 0일이다.
3. `docs/FORECAST.md`의 규칙(삽입 전용 예측 기록, 자료 마감 시각, 결과 분리)을 지키려면
   새 테이블과 새 스케줄이 필요한데, 이번 요청에서 둘 다 금지다.

다시 볼 조건: 일별 프로필이 8주 이상 쌓이고, 결과로 쓸 수 있는 공식 자료(시간대별
실제 여객 등)가 확인되고, 소유자가 저장·스케줄 추가를 승인할 때.
