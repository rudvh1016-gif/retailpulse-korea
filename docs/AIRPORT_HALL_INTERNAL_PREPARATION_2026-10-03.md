# 출국장 예상 인원 내부 연결 준비 — 공개 보류

공개 정책은 바꾸지 않는다. `NEXT_PUBLIC_AIRPORT_HALL_SIDES` OFF와
`halls: null / hallsWithheld: true`를 유지한다. 이 변경을 병합하거나 배포하지 않는다.
자료를 화면에 추가하거나 가상 인원을 모형에 넣지 않는다.

## 연결 결함과 작은 수정

기존 요약은 출국장 개별 행(`is_aggregate=0`)만 `summarizeHallSides`에 전달했다.
함수는 공식 합계(`t1dgsum1 / t2dgsum2`)와 대사해야 동서 값을 인정하므로,
공개 조건이 충족되더라도 플래그만 켜면 합계가 없어 값을 산출할 수 없었다.

이미 읽는 `passengerForecastRows` 조회는 그대로 둔다. 정규화 계약에 따라
터미널별 공식 출발 합계 필드명(`t1dgsum1 / t2dgsum2`)을 내부 사본에만 붙인다.
기존 출국장 조회에 `direction`을 투영한다. 두 조회의 WHERE, LIMIT, 바인딩과 배치 개수는
유지한다. 새 조회·인덱스·쓰기·제공자 호출·스케줄은 없다. 정책 OFF에서는
개별 행 조회의 기존 거짓 조건을 유지하고 내부 결합도 하지 않는다.
조건을 나중에 충족했을 때만 같은 서비스 날짜의 기존 공식 출발 합계와
개별 행을 결합할 수 있도록 준비한다. 입국 합계와 현재 관측 대기인원은 제외한다.

중복 개별 행·중복 합계·같은 시간대의 `23_00 / 23_24` 중복은 첫 행을
임의 선택하거나 합하지 않는다. 한 시간 구간, 필드 완전성, 공식 합계 대사,
24시간 완전성이 충족될 때만 해당 인원 집계가 성립한다. 빈값은 0으로
바꾸지 않고 TOTAL 행은 25번째 시간대로 넣지 않는다.

T1 6번은 교통약자 우대 출구이며 공식 예상혼잡도 대상에서 제외된다.
그 필드의 0을 실제 수요 0으로 읽지 않도록 내부 집계에
`T1_HALL_6_OUTSIDE_EXPECTED_CONGESTION` 한계를 기록한다. 현장 이동량이나
탑승구·매장별 승객을 나타내지 않는다. 동서 분류는 출국장 위치를 근거로 한
KORETAIL의 합산이며 기관의 원본 동서 인원 필드가 아니다.

SQLite 실제 스키마 단위 검증은 기존/변경 출국장 SELECT의 접근 계획과 반환 행 수,
요약의 단일 30문장 배치, OFF 상태 개별 반환 0행과 동일한 공개 응답을 확인한다.
Production D1의 공식 rows_read·CPU 실측은 자격 증명이 없어 미실행이며
이 로컬 검증을 공식 사용량 측정으로 주장하지 않는다.

## 문의 경로와 확인 사항 — 발송하지 않음

2026-10-03 [공식 데이터 상세](https://www.data.go.kr/data/15095066/openapi.do)는
관리부서를 **인천국제공항공사 인프라DX팀**으로 표시한다. 해당 페이지의
**오류신고 및 문의**가 확인 가능한 공식 온라인 경로다. 실제 발송 전
수신 부서·문구 협의 담당자를 소유자가 확인해야 한다. 공개 페이지에서
관리부서 전화번호 값은 확인되지 않았으므로 이메일·직통번호를 추정하지 않는다.
포털 운영지원 연락처를 공항 관리부서 연락처로 대신 쓰지 않는다.

기존 미발송 초안은 `docs/AIRPORT_SIDES_2026-09-29.md` 4장에 있다.
최소 확인 사항은 다음과 같다.

1. 기존 터미널 전체 예고와 새 출국장 위치 기준 합산의 안내 문구가 조건을 충족하는지.
2. T1 동 1·2·3 / 서 4·5·6, T2 동 2 / 서 1의 명칭과 T1 6번 제외 한계를 어떻게 알릴지.
3. 날짜·시간대·자료수집 시각·출처, 예상치이며 실제 이동·대기·매장 방문 인원이 아니라는 문구.
4. 직원 공유 문구·저장 이미지에도 같은 조건이 적용되는지.

A5에 별도 발표 시각이 확인되지 않으므로 기존 초안의 “발표·수집” 표현을
확정된 발표 시각으로 취급하지 않는다. 대상 시간과 자료수집 시각을 구분한다.
협의 완료 기록·원천 인증 응답·현재 개별 저장 완전성을 확인하기 전에는
공개 가능하다고 확정하지 않는다. 소유자의 디자인·배포 승인은 관리부서의
문구 협의 완료 증거와 구분한다.

단위 테스트 1,130개, 추가 회귀 테스트 11개, lint/typecheck, 빌드와 렌더 HTML 42개,
전체 Git 이력·작업 파일 비밀정보 검사가 통과했다. 기존 설정 기반 health 검사도 통과했다.

브라우저 재검증 결과를 저장소 안 outputs 폴더에 둔 첫 재시도에서는 Vite가
브라우저의 잠긴 Cookies 파일을 감시해 EBUSY로 종료했다. 테스트 결과를 사용자 Temp로
옮겨 같은 테스트를 재실행하며, 제품 코드·테스트 조건·시간 제한은 바꾸지 않았다.

최종 동일 테스트 재실행은 브라우저 E2E 480개 전부 통과(4.3분)했다.
