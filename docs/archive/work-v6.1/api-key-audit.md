# RetailPulse Seoul — API Key · Free Use · Failure Audit

기준일: 2026-08-23 KST  
판정 원칙: `무료 발급`, `무료 개발호출`, `무료 운영`, `상업 이용`, `재배포`, `무제한`을 서로 다른 항목으로 본다.

## 1. 결론

- **현재 Site가 방문 시 직접 호출하는 외부 공공 데이터 API는 0개다.**
- 현재 사용 중인 실제 데이터는 인천공항 월별 실적과 서울 단기체류 외국인 생활인구의 **검증된 정적 Official Historical 집계 2개**다.
- 오늘·내일 Pulse, 운항편, 게이트 Wave, 매장 신호는 Live API가 아니라 `DEMO`다.
- 공항 최소 Live 구성은 **공공데이터포털 프로젝트 서비스키 1개 + API별 활용신청 3건**으로 정리한다. 별도 비밀키 3개로 세지 않는다.
- 아래 3개 공항 API는 공식 페이지에 `비용부과유무: 무료`로 표시되어 있다. 다만 개발 호출량 제한과 운영계정 심의가 있으므로 `무제한 무료`는 아니다.
- 실제 고객 서비스 전체 P0는 위 공공데이터포털 키 외에 **서울 열린데이터광장 키 1개**가 추가로 필요하다. 기상청 단기예보는 공공데이터포털에서 같은 프로젝트키를 선택하되 별도 API 활용신청을 한다.
- 여객예고는 공식 웹페이지·Excel 공개를 확인했지만 자동화용 OpenAPI 계약은 확인되지 않았다. 따라서 검증 전에는 `KEY_REQUIRED`가 아니라 `AUTOMATION_REVIEW`다.

## 2. 공항 최소 Live — 키 1개, 활용신청 3건

공공데이터포털의 활용신청 화면은 기업회원에게 `프로젝트 서비스키` 또는 `개인 서비스키`를 선택하게 한다. 이 구조를 기준으로 하나의 프로젝트키를 아래 서비스의 권한에 연결한다. **키를 하나 골라도 API 활용신청과 호출한도는 서비스별이다.**

| 활용신청 | 공식 범위 | 개발한도 | 운영 | 비용 | 이용허락 | 핵심 한계 |
|---|---|---:|---|---|---|---|
| [항공기 운항 현황 상세](https://www.data.go.kr/data/15140153/openapi.do) | D-3~D+6, 출발·도착, 항공사, 편명, 터미널, 게이트, 체크인, 상태 등 | 500회/일 | 활용사례·URL 기재 후 심의, 안내상 최대 100,000회/일 | 무료 | 제한 없음 | 실시간 여객 수가 아니라 운항편 정보 |
| [출국장 혼잡도](https://www.data.go.kr/data/15148225/openapi.do) | 출국장 1~6, 동·서, 수집시각, 대기인원, 약 1분 | 1,000회/일 | 심의 후 증설 | 무료 | 제한 없음 | **T1만 제공, T2는 추후 제공 예정** |
| [입국장 현황](https://www.data.go.kr/data/15095061/openapi.do) | H-2~H+2, T1/T2, 도착편, 항공기·입국장 게이트, 내·외국인 대기인원 | 500회/일 | 심의 후 증설, 안내상 10,000회/일 | 무료 | 제한 없음 | 전체 공항 장기 History가 아니라 짧은 운영창 |

### 무료의 정확한 뜻

- API 이용료는 0원이다.
- 개발계정 일일 한도 초과 시 호출이 거절된다.
- 운영 트래픽 증설은 자동 보장이 아니라 서비스 URL과 활용사례를 포함한 심의 대상이다.
- 서버, 저장소, 모니터링, 장애대응 운영비까지 0원이라는 뜻은 아니다.
- `이용허락범위 제한 없음`은 데이터 이용허락 정보다. 최신 운항상태를 그대로 보장하거나 서비스 수준을 보증한다는 뜻은 아니다.

## 3. 여객예고는 왜 키 수에서 뺐나

[인천공항 공항 예상 혼잡도](https://www.airport.kr/ap_ko/883/subview.do)는 공식 화면과 Excel 다운로드를 제공한다. 공식 안내상:

- 출국 여객예고: D+2
- 입국·환승 여객예고: D+1
- 매일 17:00 갱신
- 터미널·시간대·출입국장 단위 표시

그러나 공개 페이지에서 자동화용 OpenAPI 상품, 키, 쿼터, 운영허락 계약은 확인되지 않았다. 화면 HTML을 무단 크롤링하는 방식은 채택하지 않는다. Production은 다음 중 하나가 확인된 뒤 연결한다.

1. 인천공항 Open Data Portal의 공식 API 상품 승인
2. 공식 Excel의 자동수집 허용조건 확인
3. 담당부서의 서면 활용 확인

## 4. RetailPulse 전체 P0 Credential Map

| Secret/계정 | 필요한 작업 | 현재 판단 |
|---|---|---|
| `DATA_GO_KR_SERVICE_KEY` | 공항 3 API 각각 활용신청. 기상청 단기예보도 같은 프로젝트키로 별도 신청 | **필수 1개** |
| `SEOUL_OPEN_DATA_KEY` | 서울 단기체류 외국인 최근 API, 서울 실시간 도시데이터 | **필수 1개** |
| 인천공항 여객예고 자동화 권한 | ODP/API 또는 Excel 자동수집 조건 확인 | `AUTOMATION_REVIEW` |
| Naver Client ID + Secret | Search/Shopping 상대 관심도 | 선택 P2, 초기 Live에 불필요 |
| ECOS API Key | 환율 보조 Feature | 선택 P1 |
| TourAPI 활용신청 | 행사·관광지·다국어 POI | 선택 P1, 상품별 조건 검토 |

따라서 **공항 최소는 비밀값 1개**, **RetailPulse 핵심 Live는 현재 확실히 필요한 비밀값 2개**로 정리한다. “총 3개의 서로 다른 키가 필수”라는 표현은 쓰지 않는다.

## 5. 기상청 무료 여부

[기상청 단기예보 조회서비스](https://www.data.go.kr/data/15084084/openapi.do)는 공식 페이지상:

- 비용: 무료
- 개발계정: 10,000회/일
- 개발·운영: 자동승인 안내
- 이용허락: 공공저작물 출처표시 제1유형
- 인증: 공공데이터포털 서비스키

따라서 공항 키와 별개의 새 비밀 문자열로 세기보다 같은 공공데이터포털 프로젝트키에 기상청 API 권한을 추가하는 구조로 설계한다.

## 6. 서울 API

서울 열린데이터 API는 URL에 서울 인증키를 요구한다. 서울 실시간 도시데이터는 한 번에 한 장소씩 호출하며, 공식 안내상 샘플키는 제한된 장소만 조회한다. Production은 서울 키를 Frontend에 넣지 않고 Collector Secret으로 보관한다.

## 7. 버그가 없다고 보장할 수 없는 이유

공식 API도 다음 실패를 명시한다.

- 잘못된 파라미터
- 서비스키 누락·미등록·기간 만료
- API별 권한 없음
- 일일·초당 호출량 초과
- 기관 API timeout 또는 Gateway 오류
- 제공기관 Schema/필드 변경
- 특정 터미널·시간대 0건 또는 미제공

따라서 `무료`와 `버그 없음`은 같은 뜻이 아니다. Production Collector는 반드시 `timeout → retry with jitter → schema validation → last-known-good cache → stale label → source-only fallback` 순서로 처리한다.

## 8. 고객 오해 방지 수정

이번 감사에서 고객을 오해시킬 수 있던 다음 문제를 수정했다.

- More의 `Updated 12m ago`, `Updated 35m ago` 등 Demo freshness를 실제 Live 업데이트처럼 보이게 하던 표시를 제거했다.
- 현재 상태를 `Official Historical 2개 / Live API 0개`로 바꿨다.
- 여객예고를 검증되지 않은 `KEY_REQUIRED`로 단정하지 않고 `AUTOMATION_REVIEW`로 변경했다.
- 입국장 현황 API를 Data Catalog에 누락했던 문제를 보완했다.
- 공항 키 개수와 API 활용신청 개수를 별도로 표시했다.

## 9. 배포 전 승인 기준

아래가 모두 통과해야 `LIVE`로 표시한다.

1. 각 API 활용신청 승인
2. Secret이 서버에만 저장됨
3. 정상 수신 및 0건 응답 구분
4. Schema validation
5. KST source timestamp
6. 호출한도 모니터링
7. T1/T2 미제공값 복제 금지
8. 장애 시 Official Historical 유지
9. 운영계정 및 트래픽 증설 승인
10. 최신 이용조건 재확인
