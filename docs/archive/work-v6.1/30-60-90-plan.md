# RetailPulse Korea — 30 / 60 / 90 Day Production Plan

## First 30 days

- Make the site publicly accessible on the approved `.com` domain.
- Obtain only verified-free API applications/keys and required operating approvals.
- Build collectors, normalizer, source-status checks and free storage.
- Backfill official history with source/version records.
- Start immutable prediction and outcome archives before promoting forecasts.
- Connect live airport/weather/Seoul signals with caching and degraded mode.

## Days 31–60

- Freeze target definitions and baseline implementations.
- Run Forecast V1 in shadow mode; begin FAST matching and scoreboard coverage.
- Monitor schema changes, freshness, quota use and collector failures.
- Measure organic landing visits, language split, return visits and Business usage without sensitive tracking.

## Days 61–90

- Add DEEP outcomes only where licence, mapping and lag are documented.
- Report target/area/industry coverage and baseline improvement honestly.
- Test one challenger in shadow; no automatic promotion.
- Collect user feedback and decide continue, narrow, or maintenance mode.

Success is not feature count. Continue active development only if at least one is demonstrated: baseline improvement on a matched target, organic growth, returning use, credible user feedback, or material portfolio/career value.
