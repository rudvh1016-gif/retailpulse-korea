## 2b. 공항 첫 화면과 흐름 그림의 모양 (2단계, 8차 판정 뒤 확정)

여덟 번의 소유자 판정을 거쳐 **노을 포스터**(방향 B)로 확정했다 (`app/airport-visual.css` `.airport-hero`, `app/airport-flow-figure.tsx`).

- 공항 출국 첫 화면의 앞부분(범위, 하루 숫자, 산식·한계, 흐름 그림)은 카드 없이 **화면 끝까지 이어지는 노을 하늘** 위에 놓인다: 위는 `--night`(해 진 뒤의 남색) → `--dusk-deep` → `--dusk` → `--sky-500` → `--rose`(하늘이 복숭아빛과 만나는 띠) → `--cloud-400` → `--cloud-200` 지평선. 시각 계층에서 유일한 CSS 그라데이션이고, 패널 밖 페이지는 흰색 그대로다(순백 시험은 `.airport-hero` 안을 그림으로 보고 제외).
- 숫자 하나: 흰색, Pretendard 300 굵기, 72–132px, 자간 -.055em. 설명은 모두 작고 조용한 흰 문장(중점으로 이은 메타 글줄 대신 문장형 — `passengerCopy.scopeSentence`, `flowCoverageSentence`).
- 하루 승객은 지평선 위 **빛나는 흰 구름**(흐름선 아래 면, 단조 3차 곡선). 지난 시간대는 짙게, 남은 시간대는 비치게. 눈금·값 라벨·범례 없음 — 모양이 자료다. 현재 분은 빛 기둥 + 흰 점선 + 흰 알약(시각) + 구름 가장자리의 점. 피크는 복숭아색 점 하나. 하늘 어디를 짚어도(포인터·터치·키보드) 그 시간대의 값(T1·T2 포함)을 읽는다.
- 입국 화면과 개인 홈은 포스터를 쓰지 않는다: 입국은 독립 하늘 그림(`.airport-flow-sky`), 개인 홈은 평범한 숫자.
- 판정 기록: 1차 막대→선(구려), 2차 남색 선+그라데이션 카드(AI 느낌·파스텔 아님), 3차 하늘·구름, 4차 색 선 제거, 5차 하늘 카드(공무원 느낌), 6차 카드 없는 밴드, 7차 문장형 문구, 8차 포스터(확정).

## 2c. 출국객 수 아래의 출발편 묶음 (2단계 후속, 2026-10-02 밤)

실서비스 포스터를 본 소유자 판정: 밴드가 너무 크고 다른 부분과 어울리지 않는다 → 숫자 56–88px, 하늘 위를 `--dusk-deep`부터(남색 `--night` 제거), 그림 높이 200/224. 그리고 "출발편 동·서편과 목적지 지역" 묶음은 결정에 중요하니 출국객 수 바로 아래로 옮기고 압도적으로 다시 디자인.

- 위치: `AirportTodaySummary` 안, 한눈에 보기 바로 뒤(`app/live-signals.tsx`). 출국 탭 끝에 있던 자리에서 올라왔다.
- 동·서편: 두 숫자(편수·비율·참고 예상 인원)가 좌우에 서고, 그 사이 3px 간격의 막대(동 `--dusk`, 서 `--cloud-600`, 막대 안에 "동편 53%"·"서편 47%"). 중앙·탑승구 미정은 그 아래 한 줄(빗금 대신 점선 테두리 견본). (`FlightSplitCard`)
- 탑승구 지도: 건물을 서편 구역(`--cloud-100`)·중앙 띠(`--haze`)·동편 구역(`--sky-100`)으로 나눠 칠하고 위쪽 띠에 "서편 N편"·"동편 N편"을 크게 적는다. 구역 경계는 표의 탑승구 위치에서 계산한다(서편 탑승구 가운데 가장 동쪽과 중앙·동편 탑승구 가운데 가장 서쪽의 중간). 게이트 번호 순으로 잇는 흰 척추선, 면적이 편수에 비례한 점(탑승동은 0.6배), 동 `--dusk`·서 `--cloud-600`·중앙 `--sky-500`·미정 빗금, 상위 8개 게이트만 숫자 표시(나머지는 hover·포커스·접근성 이름), 등장 시 한 번 커짐. T2 520px·T1 420px·탑승동 200px(너비 560px) 한도, 가운데 정렬. 범례와 설명문은 지도 아래. (`BuildingMap`)
- 목적지 지역: 한 색(`--sky-300`)의 막대 목록 + 편수·비율 + 동/서 수. 누르면 지도 필터(선택 행은 `--dusk`). 표 요소와 `data-group`은 시험 계약대로 유지.
- 3차 판정(2026-10-02 밤, "무슨 말인지 모르겠다 / 그래프가 작아졌다 / 동서편 그림을 고급화하고 눈에 잘 보이게 / 미확인이 생기지 않게"): ① 묶음의 모든 문구를 "~입니다" 문장으로 다시 씀(`lib/airport-flight-split-copy.ts`, `lib/airport-departure-map-copy.ts`, `lib/airport-sides-copy.ts`, `lib/business-prep-copy.ts`). 예: "탑승구가 정해진 98편 기준으로 동편 53%, 서편 47%. 동편이 더 많습니다." ② 그림 높이 200/224 → 232/264(작아 보인 원인은 시험 자료가 2시간뿐이던 것; 실서비스는 24시간). 피크 라벨과 현재 시각 알약이 가까우면 서로 반대쪽으로 비킨다. ③ 지도의 동·서 구역 채색과 큰 구역 라벨(위). ④ "위치 미확인"을 없앰: 공식 지도에 있는 탑승구 전부에 중앙선 규칙으로 동·서·중앙을 부여(`config/airport-sides.v1.json` 34곳 추가, docs/AIRPORT_SIDES_2026-09-29.md §3). 남는 것은 지도에 없는 탑승구 10곳의 항공편과 아직 탑승구가 정해지지 않은 항공편뿐이며 화면 이름은 "탑승구 미정"이다. 글꼴 부분집합 밖의 음절(몫·뺍·똑·슷 등)은 쓰지 않는다(`tests/font-coverage.test.mjs`).
- 파스텔 색은 dataviz 검증기의 채도 하한 아래다(설계상). 식별은 색만으로 하지 않는다: 각 표시 옆의 단어, 범례, 피어 위치, 숫자. CVD 분리(ΔE ≥ 15)와 일반 시각 분리는 통과.

## 3. 글자

글꼴은 이미 Pretendard다(`KORETAIL Sans Variable` = Pretendard 부분집합 개명본, 변수 굵기 45–920; 전체 Pretendard는 유니코드 범위 조각으로 함께 있다). 무료 한글 UI 글꼴 중 가장 널리 쓰이는 선택이라 **가족은 바꾸지 않고 굵기·크기·자간으로 고급스러움을 만든다**: 큰 숫자 540 굵기·자간 -.04em, 그림 안 숫자 620, 축 글자 500·자간 .04em. 다른 가족(SUIT, Paperlogy 등)은 글꼴 서브셋·프리로드 시험을 함께 바꿔야 하므로 5단계에서 증거와 함께 결정한다.


- 큰 숫자 하나(`.av-display`, 40~72px, 고정폭 숫자) + 작은 설명 한 줄. 숫자 옆 단위는 작게.
- 제목은 지금처럼 눈썹(eyebrow) 대문자 + 문장형 제목. 새 글꼴을 추가하지 않는다(글꼴 서브셋 시험이 막는다).
- 설명은 한 문장. "~입니다"로 끝나는 안내문을 두 줄 넘게 쌓지 않는다.

## 4. 움직임 (lib/motion.ts, GSAP 3.15 Standard no-charge licence)

- 움직임은 **자료가 들어오는 과정**을 보여줄 때만: 숫자 카운트업, 막대·호·선이 자라남, 하루 재생. 장식용 움직임·반복 움직임·배경 움직임 금지.
- 한 번만, 0.56초(reveal) 또는 0.24초(state), ease-out. 등장 순서는 읽는 순서.
- GSAP은 그림이 처음 움직일 때만 불러온다(동적 import). 첫 화면 JS에 포함되지 않는다 — `tests/visual-foundation.test.mjs`가 정적 import를 막는다.
- 작은 드러냄(숫자 카운트업, 선이 그려짐)은 `lib/motion.ts`의 `tween`(requestAnimationFrame)으로 자료가 도착한 순간 바로 시작한다. 라이브러리를 기다리지 않는다. GSAP은 순서가 있는 그림(3단계 하루 재생부터)에만 쓴다.
- `prefers-reduced-motion`이면 최종 상태를 바로 그린다.
