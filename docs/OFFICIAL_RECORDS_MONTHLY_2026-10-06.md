# 공식 ‘기록’ 월별 화면 — 로컬 인계

기준 main: `ef0e98c79ab92bafe5418c8baea0e62329d0c126`.
독립 브랜치: `feat/official-records-monthly-20261006`.
대상: `/ko/forecast` 및 같은 경로의 en/zh/ja. 여행 사진 기록이 아닌 상단 ‘기록’ 탭이다.
커밋·푸시·PR·병합·배포는 실행하지 않았다. 공개 단계는 부모 담당에게 인계한다.

## 최종 동작

- 기존 ‘숫자 하나가 무슨 뜻인지부터 / 지금 지역 상황’에서 `HomeTodayBrief` 반복을 제거했다.
- 지역 4곳과 보관 범위 내 월 선택 → 선택한 달과 전월의 일평균 체류 인구 범위를 나란히 표시한다.
- 각 달의 포함 일수/마감일까지 날짜 수, KST 마감일을 표시한다. 현재 월은 오늘을 제외하는 집계 중 표시가 있다.
- 일별 범위를 그리되 결측·불완전한 날은 숫자 0으로 만들지 않는다. 계산법·보관 범위·일별 포함/제외 내역은 접는다.
- 기존 터미널 비중·외국인 생활인구·예측 검증 안내는 별도 ‘공식 장기 통계’ 접기에 보존했다. 이 고정 장기 통계는 위 월 선택의 범위가 아니다.
- 기존 검정 글자·글자 크기 체계와 서울 페이지 디자인을 유지했다. 상단/하단 탐색이나 공항 대기 카드 파일은 바꾸지 않았다.

## 집계 정의

원자료는 기존 D1 `seoul_realtime_area`의 `SEOUL_CITYDATA_PPLTN` 관측이다. 새 외부 API, 수집기, 테이블, 마이그레이션, 계정, 서비스는 없다.

1. 한국시간 00~23시 각 시간 구간에서 마지막 저장 관측을 하나 선택한다. 같은 시간의 여러 관측을 더하지 않는다.
2. 같은 지역·지역 코드·출처·정의(schema), LIVE 원본·VALID 품질·정상 최솟값/최댓값만 인정한다. 비교 양쪽 모두 마지막 유효 저장 관측의 동일 정의를 사용한다.
3. 24개 시간 구간 모두 유효한 날만 하루 평균을 계산한다. 최솟값·최댓값을 따로 평균한다. 한 시간이라도 없거나 정의가 달라지면 그 날은 제외한다.
4. 각 완결일에 동일 가중치를 주어 월 평균을 구한다. 결측·미완결·진행 중인 오늘·미래는 분모에 넣지 않는다.
5. 현재 월은 전날까지의 완결일, 전월은 달 전체의 완결일이다. 포함 일수가 다른 부분 기록일 수 있음을 표시한다. 달이 바뀌면 마지막 날까지를 자동 계산한다.
6. 기존 `rangeChange`로 증감 범위를 계산한다. 중간값·정밀 단일 %·일 방문객 총합을 만들지 않는다. 0 기준값은 증감 계산 불가다.
7. 화면의 인원 하한은 내림, 상한은 올림한다. 계산은 반올림 전 값으로 한다.

이는 하루 고유 방문객 수나 서울시 공식 일별 총계가 아니라, 저장된 시간별 공식 관측을 KORETAIL이 계산한 일평균 체류 인구 범위다.

공식 출처 직접 확인: https://data.seoul.go.kr/dataList/OA-21285/A/1/datasetView.do (2026-10-06).
해당 페이지는 자료를 ‘실시간 인구현황’으로 설명하고, 단기체류 외국인(90일 이하)을 인구 추정에서 제외한다고 명시한다. 같은 제한을 접기 안에 표시했다. 공식 사이트는 별도 과거 API 이력을 제공하지 않으므로 기존 보관 자료만 사용한다.

## 실제 데이터 범위와 검증 한계

공개 `/ko/forecast`를 직접 열어 변경 전 본문과 이미지 픽셀을 확인했다. 부모가 확인한 Library 참고 이미지의 대체 경로로 허용된 공개 동일 화면이다. Windows의 알려진 Library 로컬 메타데이터 제한을 우회하지 않았다.

공개 기존 `/api/live/summary?month=...`에서 확인한 `dateAvailability.seoulObserved`:

| 조회 월 | 하나 이상의 서울 관측이 존재하는 날짜 |
| --- | --- |
| 2026-08 | 28, 31 |
| 2026-09 | 1~30 |
| 2026-10 | 1~6 |

근거: `outputs/records-public-data-audit.json`의 조회 시각·API 생성 시각·응답값. 위 날짜는 지역 합동 존재 검사이며 특정 지역의 완결일 수가 아니다. 공개된 기존 API로는 시간별 전체 표본을 읽을 수 없으므로 운영 데이터의 지역별 24시간 완결일 수와 실제 월평균은 이번 로컬 작업에서 확정하지 않았다.

새 기록 읽기 경로는 실제 운영 DB가 응답하는 최초/최종 저장 날짜와 완결일 수를 그대로 표시한다. 오래된 달을 임의로 채우거나 8월부터 매일 수집됐다고 주장하지 않는다. 화면 캡처의 인원 숫자는 명시적인 합성 E2E fixture이며 운영 월평균이 아니다.

## 기존 구현 재사용과 읽기 비용

- 기존 공항 MTD의 `datesBetween`·`daysInMonth`, KST 날짜 유틸과 `rangeChange`를 재사용했다. 공항 예상 승객 총합과 서울의 순간 체류 인구는 섞지 않는다.
- 기존 `/api/live/summary?view=records&area=...&month=...`에 분리된 읽기 분기를 붙였다. 일반 summary 응답과 조회 동작은 그대로다.
- 한 번의 D1 batch, 3개 statement: 보관 경계 2회 인덱스 탐색 + 선택 월 + 전월. 월당 최대 31×24개 시간 구간, 총 반환 관측 최대 1,488개, 경계 최대 2개. statement당 매개변수 최대 33개.
- 기존 `seoul_realtime_area_observed_unique(source_id,area,observed_at)`를 사용한다. 시간 조건은 인덱스 열 그대로 두며 날짜 함수는 작은 요청 달력에만 적용한다. 전체 이력 SUM/AVG/COUNT/SCAN을 하지 않는다.
- 실제 마이그레이션을 적용한 SQLite의 `EXPLAIN QUERY PLAN`에서 시간 탐색과 경계 탐색 인덱스 사용을 확인했다. 운영 D1의 과금 행 수/CPU는 측정하지 않았다.
- `worker/summary-cache-key.ts`도 함께 변경해야 한다. `view=records`, 지역, 월을 보존하며 일반 summary와 다른 지역/월이 섞이지 않게 한다. 잘못된 입력은 400, 읽기 실패는 503/no-store다. 실패를 ‘자료 없는 달’로 응답하지 않는다.
