# 뉴스 운영 저장과 저장량 점검

사용자 승인 `Sentinel_a7f4c552f68c8191b25f8344346f6c1a`는 기존 운영 D1의 SQL0026과 검토된 관세청 기사 두 건 저장에 한정한다. 새 토큰·권한, 다른 데이터 수정·삭제, 자동 수집, 공개 병합·배포는 포함하지 않는다.

## 저장하는 내용

`data/approved-news/customs-2026-10-10.json`은 검토한 실제 공식 자료 두 건의 일회성 입력이다. 화면용 fixture나 기본 seed가 아니다. 기사 ID10174903/10168489, 제목·짧은 조건별 요약, 발표·시행 구분, 출처/권리 링크와 근거·지문·첨부 검토 상태만 저장한다. PDF/HWPX/사진/HTML 바이너리나 전체 원문은 DB에 넣지 않는다. 화면은 기존 저장 API를 읽는다.

2026-10-10 UTC 로컬 측정에서 저장되는 압축 없는 UTF-8 JSON은 각각 **2,368 / 2,584바이트**, 합계 **4,952바이트**, 평균 **2,476바이트**다. SQL 열·인덱스·SQLite 페이지와 수정 이력의 추가 공간은 이 수치에 포함하지 않는다. 확인한 PDF 하나만262,958바이트이며 DB에는 링크·SHA·검토 결과만 보관한다.

## 승인된 일회성 실행

기존 `import-oneshot.yml`의 수동 입력 `sources=official_news_20261010`, `confirm=IMPORT`만 전용 경로로 연결했다. 기존 production 환경·contents:read 권한·전용 D1 토큰·직렬 실행 잠금을 그대로 사용한다. SQL0026/입력 파일 SHA, 고정 운영 DB ID, 두 기사 ID, 기존 스키마·내용을 검사한다. 다른 migration이나 기존 다른 기사에는 쓰지 않는다. 정상 migration 이력에0026 표식 한 건만 추가한다.

다른 DB, 승인 파일 변경, 부분 스키마, 기존 다른 내용은 쓰기 전에 실패한다. 첫 저장은 current2건/revision0건, 반복은 쓰기0건으로 실제 SQLite 검증했다. 원격 HTTP 쓰기는 자동 재시도하지 않는다. 결과가 불확실하면 읽기 전용으로 확인해야 한다. 원격 실행은 실제 `size_after`를 먼저 확인하며 값 누락/500MB의 보수적70% 이상이면 멈춘다. 실행 로그는 실제 쿼리 메타의 읽기·쓰기를 보고하되 계정 전체 일일 사용량으로 해석하지 않는다. 전후 DB 크기 차이는 다른 정상 수집과 겹칠 수 있으므로 뉴스만의 물리 증가로 해석하지 않는다.

## 기존 저장 최적화의 범위

`docs/STORAGE_RETENTION.md`의155MB와3.7MB/일 절감 추정은2026-09-28의 역사적 기록이다. 현재 크기는 일회성 실행의 최신 `size_after`로 따로 기록한다. 바이너리를 제외한 뉴스 저장과 unchanged-write 제거는 이번에 적용된 방안이다. 기존 예측/날씨/대기 스냅샷을 최신본만 저장하는 변경은 소비자와 재계산 범위를 추가 검증해야 하므로 실행하지 않았다.

특히 `seoul_context`는 `lib/storage-inventory.ts`와 `lib/commercial-monthly-store.ts`에서 현재·전월 월별 평균 계산의62일 원자료를 읽는다. 기존 문서의90→14일 제안은 현재 소비자와 충돌한다. 현재90일 보관을 유지하며 월 비교·재계산 원자료나 감사 근거를 삭제하지 않는다.

[Cloudflare 공식 한도](https://developers.cloudflare.com/d1/platform/limits/)는 Free 단일 DB500MB·계정5GB를 구분한다. [공식 과금 설명](https://developers.cloudflare.com/d1/platform/pricing/)에서 저장량은 표와 인덱스를 모두 포함하고, 스캔한 행을 읽기 비용으로 계산한다. 조회 LIMIT50은 반환 건수 상한이며 스캔 행50을 보장하지 않는다. 새 비용 서비스나 용량 확장은 신청하지 않는다.
