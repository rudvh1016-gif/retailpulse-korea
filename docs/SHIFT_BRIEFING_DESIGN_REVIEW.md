## 화면에서 달라지는 점

홈 상단 하위 탭의 순서를 다음과 같이 적용한다.

1. **공항한눈에**: 기존 출근 후 30초 확인·주목할 공항 흐름을 유지.
2. **내 근무 브리핑**: 저장한 근무 조건의 요약. 직접 주소는 `/{locale}?insight=briefing`.
3. **언제 몰렸나요?** 및 기존 기간 비교 탭.

브리핑은 선택했을 때만 표시·마운트하므로 숨겨진 브리핑이 지난 확인 기록을 갱신하지 않는다. 별도 날짜 제어를 제공하고 탭 이동·새로고침·뒤로/앞으로·로고 복귀를 검증한다. 기존 한눈에와 주간 비교 읽기를 공유해 중복 API 요청을 추가하지 않는다. 한국어·영어·중국어는 6개 탭, 일본어는 번역이 제공되는 한눈에·브리핑 2개 탭으로 구성한다. 일본어에 미지원 기간 분석을 노출하지 않는다.

PC에서는 근무 조건을 한 줄로 보여 주고, 현재 출발편과 비교 수치를 나란히 배치한다. 모바일에서는 읽는 순서대로 배치하되 지난주·전월 비교는 간결한 두 항목으로 유지한다. 기존 가로 스크롤 탭과 화살표·키보드 이동을 재사용한다.

처음 방문하면 터미널, 선택 사항인 매장 위치(미지정/서편/동편), 업종, 근무 시작·종료를 고르는 양식이 나온다. 업종과 근무시간은 임의로 채우지 않는다. 하루 전체를 명시적으로 고를 수도 있다. 조건 수정 중 취소하면 기존에 저장한 조건을 유지한다.

설정 후 기본 화면에는 다음 내용만 펼쳐 둔다.

1. 저장한 근무 조건과 매장 위치.
2. **터미널 전체 × 근무시간**의 출발 예정편, 출발편 최다 시간, 지난주·전월 비교.
3. 같은 범위의 **주요 출발 목적지 상위 3곳**과 정확한 편수.
4. 업종에 맞는 **매장 확인사항 2개**.
5. 자료 기준 시각, 문구 복사·이미지 저장.

전체 목적지 목록, 매장 쪽 탑승구 참고, 비교 날짜·기준 편수·포함일 등은 **구역·목적지·비교 자세히** 안에 접어 둔다. 목적지 비중 차트나 항공사·도시별 목록을 기본 화면에 추가하지 않는다.

핵심 구현은 `app/shift-briefing.tsx`의 `ShiftBriefingView`와 `lib/shift-briefing.ts`이다. 실제 홈과 디자인 검토 화면이 같은 표시 컴포넌트 및 공유 문서를 사용한다.

## 신규 진입과 기존 선택 보존

- 신규 매장 방문의 기본 장소는 **인천공항**이다.
- 전역 업종은 선택 전 `null`이다. 화장품 이미지나 화장품 점검 목록을 자동으로 보여 주지 않는다. 선택 전 공유 문서에도 미선택 상태를 표시한다.
- 기존 기기에 저장된 유효한 업종과 서울 지역은 유지한다. 과거 자동 저장된 `beauty`와 사용자가 직접 고른 `beauty`는 기존 저장 형식으로 구분할 수 없으므로 일괄 삭제하지 않는다.
- 공항에서 더보기를 거쳐 매장에 들어가면 URL로 공항·터미널 범위를 전달한다. 홈에서 터미널을 바꾸면 셸의 이동 링크에도 즉시 반영한다. 방문만으로 저장된 서울 매장을 덮어쓰지 않는다.
- 매장 탭, 준비 요약, 지역 자료, 업종 가이드는 `useBusinessContext`의 동일한 범위를 사용한다. 공유 링크로 들어온 장소와 저장된 장소가 화면 안에서 갈라지지 않게 한다.
- 공유 링크의 서울 지역은 이번 방문에만 적용한다. 실제 저장 또는 명시적 지역 선택이 있어야 기기의 기본 선택을 변경한다.
- 매장에서 바꾼 터미널·동서편은 더보기를 거쳐도 유지한다. 이전 공항 화면의 필터가 이를 덮어쓰지 않는다.
- 더보기의 **현재 설정**에는 실제 적용 중인 매장 지역·터미널·동서편을 보여 준다. 내부 서울 기본값 명동을 사용자가 저장한 선택처럼 노출하지 않는다.

기기 저장소가 차단되면 기존 구조대로 이번 방문의 메모리 상태를 사용하고 저장 실패를 알린다. 설정을 서버로 전송하는 기능은 추가하지 않는다.

## 수치의 의미와 한계

### 예정 출발편의 시간축

근무 브리핑은 선택한 날짜·근무시간의 **예정 출발시각 기준 항공편**을 읽는다. 출국장 이용 시각, 실제 운항 완료, 여객 수, 매장 방문 수, 매출로 해석하지 않는다. 근무시간은 시작 포함·종료 제외 범위다. 취소 편을 제외하고 동일 물리 항공편은 최신 행으로 판단한다.

기본 요약의 합계·집중 시간·과거 비교·목적지 집계는 모두 **선택한 터미널 전체 × 근무시간**이다. `ShiftBriefing`의 기본 선택기 호출은 `side: null`을 사용한다. 매장 위치를 서편으로 저장해도 동편 항공편을 기본 합계나 목적지 목록에서 제외하지 않는다. 특정 구역 고객의 다른 구역 방문 여부나 방문 비율을 계산하지 않는다.

터미널 전체 T1 집계에는 탑승동이 포함된다. 터미널을 확인하지 못한 항공편은 임의 배분하지 않으며, 완전한 합계나 순위를 보장할 수 없으면 확인된 편수와 부분 자료 상태를 표시한다.

### 매장 위치와 접힌 구역 참고

저장한 동·서편은 사용자의 **매장 위치**다. 화면에 서편 근무/동편 근무로 표시하며, 고객이 그 구역에만 머문다는 뜻으로 사용하지 않는다. 선택한 위치가 있으면 별도 `areaReference`를 계산해 접힌 상세에서만 보여 준다.

구역 참고는 해당 동·서편과 중앙의 탑승구를 포함한다. T1의 구역 참고는 본관에 한정되며 탑승동은 제외한다. 구역을 확인하지 못한 항공편은 추정 배분하지 않는다. 상세에는 **탑승구 위치 기준이며 매장 방문 구역을 뜻하지 않습니다**를 표시한다.

현재 저장 계약에는 **터미널별 시간대 자료**와 **하루 전체 동서편 자료**가 별도로 있고, 동서편 × 근무시간의 교차 이력은 없다. 따라서 접힌 구역 참고에 구역별 지난주·전월 비교를 만들어 넣지 않는다. 기본 화면의 비교는 현재 합계와 같은 터미널 전체 범위로 제공한다.

과거 시간대는 1시간 단위다. 07:30처럼 분 단위 경계가 있으면 현재 자료는 읽을 수 있어도 과거를 비례 배분해 비교하지 않는다. 자정을 넘는 근무는 다음 날짜 자료가 필요하므로 이번 구현에서는 집계하지 않는다. 이 제한을 화면에 설명한다.

### 주요 출발 목적지

목적지는 기본 합계와 **같은 날짜·터미널·근무시간·중복 제거 항공편**에서 계산한다. 기존에 검토된 공항→국가·지역 매핑을 사용하며, 항공사나 승객 국적을 추정하지 않는다. 기본 화면은 편수순 상위 3곳, 접힌 상세는 전체 확인 목록을 표시한다. 표시는 국가·지역명에 `행`을 붙이고 정확한 항공편 수를 함께 제시한다.

목적지 옆에는 **국가·지역 기준 · 승객 국적과 다름**을 항상 표시한다. 목적지가 확인되지 않은 편은 별도 미확인 수로 보존하고 국가에 임의 배분하지 않는다. 항공편 범위가 부분 자료이거나 목적지 매핑에 누락이 있으면 **확인된 목적지 기준 · 전체 순위 미확정**으로 표시한다. 미확인 목적지를 0편이나 다른 국가로 대체하지 않는다.

목적지 분포는 이전 확인 서명에도 포함한다. 총편수가 같더라도 국가별 편수가 바뀌면 이전 확인 이후 변화가 없다고 처리하지 않는다. 항공편 수를 여객 수·국적별 고객 수·매장 방문 가능성으로 변환하지 않는다.

### 지난주와 전월

지난주는 7일 전의 같은 근무시간과 비교한다. 전월은 전월 달력 기간 중 검증을 통과한 날짜의 같은 근무시간 평균을 사용한다. 전월 자료가 일부만 있으면 **전월 확인일 평균**으로 명명하고 포함 날짜 수/전체 날짜 수를 표시한다. 일부 수집분을 완전한 전월 평균으로 표현하지 않는다.

분모가 0이면 증감률을 만들지 않는다. 실제 0편과 자료 누락을 구분한다. 숫자와 퍼센트의 표시 반올림은 기존 증감 표시 컴포넌트를 사용한다.

## 매장 확인사항 2개 · v3

`lib/shift-store-checks.ts`의 `buildShiftStoreChecks(industry, lang)`이 업종별 기본 확인사항을 제공한다. 항공 자료나 목적지를 입력받지 않으며, 현재 재고·행사·수요를 알아낸 것으로 표현하지 않는다. **업종별 기본 체크 · 실제 상태는 매장에서 확인**을 표시한다. 항공 자료가 없어도 이 기본 체크는 사용할 수 있다.

기본 화면에는 다음 두 제목과 요약만 보인다. 각 항목 전체가 native `details`의 펼치기 영역이며, 선택하면 구체적인 확인 순서 세 개를 보여 준다. 완료하지 않은 일을 완료 표시로 오해할 수 있는 체크 표시는 사용하지 않는다.

| 패션·잡화 제목 | 기본 요약 |
| --- | --- |
| 진열 상품·재고 | 모델·색상별 판매 가능 재고와 품절 대안 정리 |
| 가격·혜택 안내 | 표시 가격·최종 결제 금액과 행사 적용 조건 대조 |

진열 상품·재고 상세:

1. 진열·행사 상품의 모델·색상을 실제 판매 가능 재고와 대조하고, 예약·불량 등 판매 제외 수량을 구분한다.
2. 품절 상품에 안내할 대체 모델·색상을 정리하고, 확정된 입고일만 공유한다.
3. 상자·더스트백 등 해당 포장재를 보충하고, 재고 보충·포장 담당과 결제 후 인계 지점을 정한다.

가격·혜택 안내 상세:

1. 현재 승인된 매장 공지의 행사 기간·대상 상품·제외 조건을 확인한다. 행사가 없으면 정상 판매 기준을 사용한다.
2. 해당 행사에 있는 중복 할인·회원/카드 조건·혜택 한도를 확인하고, 표시 가격과 최종 결제 금액을 조건에 맞게 대조한다.
3. 불명확한 문의를 넘길 담당자를 정하고, 직원에게 확인된 가격·혜택 조건만 공유한다.

8개 업종과 업종 미선택, 한국어·영어·중국어·일본어를 지원한다. 식음료는 판매 가능한 메뉴·포장재·주문/제조/픽업 분담과 메뉴 가격·안내, 뷰티는 색상·용량별 재고·테스터·현재 증정 행사 등 해당 업무로 바뀐다. 업종 미선택은 공통 매장 확인사항을 사용한다. 어떤 경우에도 목적지로 고객 국적·사용 언어·구매 수요를 확정하지 않는다.

피팅룸이나 특정 프로모션이 모든 매장에 있다는 가정은 두지 않는다. 매장 고유의 확인 결과를 새로 입력·저장하는 별도 기능이나 매일 새롭게 바뀐 것처럼 보이는 자동 문구는 추가하지 않는다.

### 모바일 배치 보완

- 자료 없음·로딩 문구는 현재 수치 영역 전체 폭을 사용한다.
- 설정·펼치기·공유 버튼 및 하루 전체 라벨은 최소 높이 44px로 맞춘다.
- 출발편 최다 시간의 시간 범위와 `24 flights` 같은 편수 표현은 각각 한 덩어리로 줄바꿈한다.
- 긴 목적지 이름은 생략하지 않고 줄바꿈하며, 같은 행의 편수 기준선을 맞춘다.
- 준비사항 상세와 공유 문구는 본문 폭 안에서 자연스럽게 줄바꿈한다. 기본 글자 크기와 기존 흰 배경·얇은 구분선은 유지한다.

## 공유와 저장

기존 `PrepShare`의 텍스트 복사·이미지 저장·공유 흐름을 작은 형태로 재사용한다. 텍스트와 이미지에는 같은 날짜, 근무 조건, 터미널 전체 범위, 수치, 주요 목적지, 비교 기준, 준비사항, 출처·한계 설명을 사용한다. 목적지와 승객 국적의 구분도 공유 문서에 포함한다. 예시 화면에서 내보낸 문서에는 **시안용 예시 자료**가 포함된다.

v3 공유 문서에는 준비사항의 두 제목·요약을 사용한다. 화면에서 상세를 펼쳐도 공유 문서에 여섯 단계를 자동으로 늘리지 않아, 직원에게 전달할 기본 요약은 간결하게 유지한다.

복사 또는 이미지는 저장 시점의 스냅샷이며 이후 실시간으로 바뀌지 않는다. 복사 API가 없는 환경에서는 선택 가능한 텍스트를 제공한다. 저장 또는 공유 요청 성공을 타인에게 전달 완료로 표시하지 않는다.

## 로컬 디자인 검토와 재생성

`app/shift-briefing-preview.tsx`는 실제 표시 컴포넌트를 예시 자료로 렌더링한다. 기존 위·아래 영역은 삽입 위치를 확인하기 위한 문맥용 화면이다. 모든 예시 수치는 실제 운영 자료로 사용할 수 없으며 화면에 예시임을 표시한다.

검토 상태는 처음 방문, 설정 완료, 변화 없음, 자료 없음, 일부 자료의 5개다. PC와 모바일 320/360/390/430px, 네 언어, 긴 목적지명 예시, 브리핑만 크게 보기 기능이 있다. 검토 화면의 저장은 미리보기 상태에만 적용한다. 긴 목적지 예시는 DXB/LHR/AKL을 사용하는 검토 자료이며 운영 항공 자료를 변경하지 않는다.

로컬 개발 경로:

```text
/ko/shift-briefing-preview?state=saved&width=desktop
/ko/shift-briefing-preview?state=first&width=mobile
```

`app/[locale]/shift-briefing-preview/page.tsx`는 production 환경에서는 `notFound()`를 반환한다. 검색 인덱싱도 비활성화한다. 검토 전용 경로를 운영 공개 페이지로 배포하는 계획은 없다.

자체 포함 HTML을 만드는 명령:

```sh
node scripts/build-shift-review.mjs artifacts/shift-review/koretail-shift-review.html
```

원하는 출력 경로를 마지막 인자로 지정할 수 있다. 생성 파일은 React 코드, 스타일, 기존 글꼴과 국기 이미지를 포함하며 외부 데이터 요청 없이 예시 화면을 연다. 국기는 기존 저장소 자산을 HTML 안에 넣으므로 별도 웹 서버 없이도 표시되도록 구성한다. 출력 HTML과 스크린샷은 검토용 산출물이고 소스에 중복으로 넣지 않는다. 검토용 기본 상태는 URL의 `state`, `width`, `size=320`, `focus=briefing`, `names=long`으로도 지정할 수 있다. 자체 포함 HTML은 `lang=en` 등으로 시작 언어도 지정할 수 있다.

## v1–v3 당시 코드 보존 상태와 배포 분리 (역사적 기록)

로컬 브랜치 이름은 `design/my-shift-briefing`이다. 첫 시안의 GitHub 보존을 시도했으나 첫 blob 생성 요청이 응답 지연으로 중단됐다. 그 blob의 원격 성공 여부는 미확인이며, tree·commit·branch ref·PR 생성은 호출하지 않았다. 따라서 **원격 브랜치와 Draft PR은 생성 완료로 보고하지 않는다.** 첫 시안은 위 로컬 커밋과 적용용 패치로 보존했다.

v3까지는 운영 반영 전의 디자인 검토 작업이었다. 그 시점에는 추가 원격 쓰기나 배포를 수행하지 않았다. 현재 v4는 위의 새로운 승인 범위에 따라 원격 브랜치·PR·CI·병합·자동 배포까지 진행한다.

현재 `.github/workflows/ci.yml`은 PR에서 검증을 실행한다. `.github/workflows/deploy-cloudflare.yml`의 자동 배포는 CI 성공뿐 아니라 원래 이벤트가 `push`, 브랜치가 `main`, 저장소가 동일하다는 조건을 모두 요구한다. 수동 배포도 `refs/heads/main`에서만 허용한다. 따라서 해당 기능 브랜치의 push나 draft PR 검증만으로 이 워크플로의 운영 배포 조건이 충족되지 않는다.

v4에서는 승인된 기본 진입·새 탭 순서를 검증하도록 `site-smoke.yml`의 화면 검증만 갱신한다. 배포 게이트·수집기·스케줄·D1 스키마는 바꾸지 않는다. NEW 공지는 기존 보고서와 기준 변경 안내를 유지하면서 브리핑 소개·직접 링크·2026-11-02 날짜를 추가하고 버전을 `shift-briefing-20261102-v1`로 갱신한다.
