# App Store 준비 인계 — 2026-10-08 KST

검토용 초안이다. 시작 main은 `bf9362466145c2f2e047b8c74daedac6fbd72e54`이며 기존 여행 기록·아이콘 검증을 재사용했다. iOS 서명 빌드, TestFlight, 실기기 검증, App Store 제출·공개는 완료하지 않았다.

## 이번 변경

- 여행 기록 상세에서 개별 삭제·사진 제거를 확인 후 실행한다. 취소·Escape는 데이터를 바꾸지 않는다.
- IndexedDB 삭제는 같은 readwrite transaction에서 revision 확인과 삭제를 수행한다. 사진 제거와 실행 취소도 기존 revision·중복·용량 검사를 통과해야 한다.
- 실행 취소는 한 변경의 원본을 페이지 메모리에만 보유한다. 해시로 목록·백업 화면을 오가도 유지한다. 새 변경은 실행 취소 또는 명시적인 마치기 후 가능하다. 페이지 종료·새로고침 후에는 메모리 사본이 사라진다. 실행 취소 중 실패하면 사본과 복구 JSON 다운로드를 유지한다.
- 삭제 실행 취소는 새 revision으로 재저장해 삭제 전 탭의 오래된 수정이 들어오는 것을 거부한다. 사진 실행 취소는 제거 후 revision을 요구하며, 다른 탭의 최신 수정을 덮어쓰지 않는다.
- JSON 복원도 새 revision token을 부여한다. 이전 v1 JSON에 revision이 없다고 다시 1로 저장하면 삭제 전 열어 둔 편집창이 복원본과 같은 revision으로 오인할 수 있어 보완했다. 기존 numeric revision은 계속 지원하고 복원 이후 수정은 새 token을 사용한다. 백업 v1 파일 형식은 바꾸지 않는다.
- 복구 JSON은 변경 전 한 기록과 사진을 담는 기존 v1 백업이다. 영구 저장 여부는 사용자가 확인해야 한다. 이미 다운로드한 백업은 삭제·사진 제거로 바뀌지 않는다.
- 사진 제거 후 같은 ID의 이전 백업을 복원하면 기존 규칙대로 건너뛴다. 사진 복구는 페이지의 실행 취소를 먼저 사용한다. 마친 후 백업으로 사진을 돌려놓으려면 현재 기록을 먼저 별도로 백업하고, 그 기록을 명시적으로 삭제한 뒤 사진이 있는 백업을 미리보기·확인하여 복원한다. 현재 기록의 후속 수정 손실 가능성을 확인해야 한다.
- 기존 여행 기록 화면을 브라우저 전용 view와 Next router wrapper로 나누고, 같은 view·폼·백업·저장 모듈로 `native/travel-client`를 빌드한다. 기존 public 개념 이미지는 동일한 파일을 native img로 표시한다.
