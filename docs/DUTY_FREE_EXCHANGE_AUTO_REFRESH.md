# 면세점 표시 환율 자동 갱신

소유자의 “환율자동갱신이무조건되어야해” 요청에 따른 구현이다. 시작 main은
`3b237c5dd5e9c2e9b6393fa8a45f2949388b0715`이며 PR313의 수동 관측과 구분한다.
이 브랜치의 코드를 직접 병합·배포하거나 생산 수집을 수동 실행하지 않는다.

## 경로와 사실 경계

- 기존 일일 GitHub Actions와 자동 생산 배포 후 환율 workflow가 공식 인터넷점 HTML을 저빈도로 읽는다.
  별도 job이므로 항공 수집 또는 KASI 실패·timeout에 의존하지 않으며 기존 D1 Write secret을 재사용한다.
- 신라 `.exchange .sum`, 신세계 `.todayRate em`의 환율 문맥만 읽는다.
  인터넷점 표시 사실이며 공항 현장 적용값·시장 환율·보장 결제액이 아니다.
  현대는 제외한다. 403/406, selector 불일치에 다른 UA·프록시·내부 API·runner로 대응하지 않는다.
- 제공자당 한 실행에서 한 요청, 유한 timeout/body 제한, 원문 HTML 저장 없음.
  기존 매일 06:07 KST 예약과 생산 자동 배포 성공 후 최초 갱신을 사용한다. 새 반복 스케줄은 없다.
  정상/일시 오류 최소 1시간 due guard, 403/406 및 영구 계약 실패는 24시간 guard다.
  실제 요청 시각을 사용하며 명목 cron 시간을 관측 시각으로 만들지 않는다.
- 업체별 canonical CURRENT 1행과 운영 attempt/lease 1행을 유지한다.
  같은 날짜·통화·환율·출처·범위는 canonical write 0회이며 실제 재검증 시각은 운영 행에 기록한다.
  CAS lease와 소유권 조건이 중복 실행·늦게 끝난 과거 실행의 덮어쓰기를 막는다.
  HTTP 이전 claim 시점에 다음 요청 가능 시각을 저장하여 실행이 끊겨 lease가 만료되어도 1시간 요청 제한을 유지한다.
- 공개 읽기 API는 저장값만 읽는다. 기존 named cache entrypoint를 재사용한다.
  쿼리는 환율 읽기 결과를 바꾸지 않으므로 하나의 canonical URL로 정규화한다.
  최대 shared TTL 300초/browser TTL 60초, KST 자정까지 남은 시간으로 TTL을 줄인다.
- 기존 설치 버튼 옆 UI는 같은 API를 15분 간격으로 보이는 동안만 다시 읽는다.
  포커스/복귀는 5분 guard, 동시 요청 1개, 자정 갱신과 unmount 취소를 적용한다.
  공급자 요청은 방문자 수에 따라 증가하지 않는다.
- 24시간 넘은 값, 이전 날짜 값, 최근 수집 실패, API 재조회 실패는 이전 확인값으로 표시하고
  원래 날짜·시각을 보존한다. 업체별 다른 값과 실패를 독립 표시한다.
  선택한 과거/미래 날짜를 오늘 환율로 채우지 않는다. 없는 값을 0으로 만들지 않는다.

## 비용 모델 — INTERNAL_ESTIMATE, 계정 전체 사용량이 아님

예약 정상 실행은 업체당 1요청/일이며 자동 배포 후 실행도 due guard를 따른다.
시간당 배포가 계속된 극단에서도 업체당 최대 24요청/일, 차단 업체는 최대 1요청/24시간이다.
한 정상 실행의 최대 canonical 변경은 2행, 운영 claim/완료는 합계 4행이다.
기본 예약 기준 최대 canonical 2행/일, 운영 4행/일이다. CURRENT 총 4행이며 raw/history 증가가 없다.
PK 두 개의 인덱스 비용을 실제 D1 meta에서 별도로 측정해야 한다.

| 방문자/일 | 10분 단일 방문의 추가 FX 읽기/일 | 최악 cache 없음 D1 읽기 행/일 |
|---:|---:|---:|
|100|100|400|
|500|500|2,000|
|1,000|1,000|4,000|
|5,000|5,000|20,000|
|10,000|10,000|40,000|
|20,000|20,000|80,000|

15분 이상 체류·재방문·복귀는 추가 사이트 요청을 만든다. 5분 guard의 장기 체류 극단은
브라우저당 288읽기/일이다. Cache HIT의 D1 읽기는 0이며 한 entry/POP의 300초 TTL은
보통 최대 288 miss/일이지만 eviction·배포·오류 no-store에서는 더 많을 수 있다.
위 수치는 기존 사이트 요청량과 합산해야 한다. 20,000 방문자 안전 또는 무료 용량 보장을 뜻하지 않는다.
70/85/95의 기존 NOTICE/PROTECT/EMERGENCY 정책을 유지하며 유료 전환 경로를 추가하지 않는다.

## 검증과 활성 상태

구현·검증 결과는 작업 중이다. 원문 직접 읽기 → parser → 저장 → API → UI의 실제 생산 성공은
별도 관측 전까지 미확인이다. 로컬 fixture/workerd 결과를 생산 성공으로 표시하지 않는다.
GitHub schedule 지연/유실과 runtime variable는 checkout만으로 확정할 수 없다.
`ENABLE_PRODUCTION_COLLECTOR`의 코드상 gate는 유지한다. 2026-10-08 07:09:46 UTC의
읽기 전용 확인에서 저장소 변수는 `true`였다. 이 브랜치는 병합되지 않아 새 환율 경로는 아직 활성화되지 않았다.
약관 동의·새 키·보안 권한·유료 서비스·수집 수동 실행은 이번 작업에서 수행하지 않는다.

## PR313 배포 후 검사의 별도 불일치

사용자가 병합한 PR313의 main `3b237c5` CI와 자동 Deploy Cloudflare는 성공했고,
공개 화면의 헤더 환율·건물별 분모·기둥 및 승인된 중복 영역 삭제를 읽기 전용으로 확인했다.
그러나 배포 후 화면 검사 [37738082803](https://github.com/rudvh1016-gif/retailpulse-korea/actions/runs/37738082803/job/113182119803)은
상위 스레드가 확인한 결과 43 통과/7 건너뜀/8 실패다.
`e2e-production/redesign-readout.spec.ts:54-55`가 삭제 승인된 `.airport-glance-strip`의 가시성을 요구하며
56-69행도 그 옛 3셀 구성에 의존한다. 현재 코드와 실제 공개 화면에서는 이 영역이 없다.
따라서 최신 승인 화면과 옛 검사 사이의 불일치이며, 환율 경로 실패나 hydration 실패라는 근거가 아니다.
이 환율 PR에서는 삭제한 제품 영역을 복원하거나 그 검사·UILock을 끄지 않는다.
배포 후 검사 파일을 승인된 새 화면의 실제 정보 구성에 맞추는 후속 작업이 남아 있다.
