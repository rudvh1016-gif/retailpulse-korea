# A4 normalized-provider bridge (unbound)

The existing T1 and T2 collectors now accept an explicit second options argument for offline/staged execution. All production callers, normal and retry, still pass only their existing environment. No binding, environment conversion, workflow, provider budget, legacy SQL, incident code, or production activation was added. Pilot dependencies are lazy-loaded after explicit opt-in and eligibility.

The collector normalizes and pages the same source response, retains only valid same-epoch distinct zones and requires explicit matching provider population before the isolated writer is selected. T1 needs an exact declared population within the existing single-page cap. T2 additionally verifies each page length and consistent declared totals; the existing one-page retry bound remains absolute. No data, unknown/unsupported observation quality, duplicate/mixed cohorts, short/unknown population, and ineligible pilot settings use the unchanged legacy destination before any shard attempt. This does not claim every normal provider response can use the shard. Draft primary statements are never executed after shard routing. No primary fallback after an attempted shard operation, including an ambiguous acknowledgement. The fixed non-network storage failure cannot request a fresh provider runner. A same-observation duplicate is suppressed without advancing shard-backed health/retrieval or rewriting that immutable generation.

Local tests stub fetch and exercise actual T1/T2 parsers using the real collector, existing retry classifier and two independent transaction-capable SQLite fixtures. The native D1 publication rollback was separately proven in the isolated writer slice. Still unverified: real staged Worker/REST equivalence, eligible-share and actual retained formats across T1/T2, provider quota/read/write metadata, rollback/retention, operational collection scope and exact generation CAS. Production normal/retry dispatch must not receive the second argument until those policy and evidence integrations are reviewed.
