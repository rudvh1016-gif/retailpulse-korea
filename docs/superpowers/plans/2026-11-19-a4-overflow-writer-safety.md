# Future A4 overflow: isolated writer evidence

This is a disconnected reference implementation; no production collector, binding, migration, scheduler, retry routing, CAS, or airport data was changed.

- The caller must explicitly select an enabled, schema-ready shard and cutover. The helper refuses disabled/unready/pre-cutover captures; it is not an automatic legacy fallback.
- The caller supplies the already-normalized single-generation T1 or T2 data, original UTC run/retrieval clocks and original SUCCESS/PARTIAL status. The helper validates identity, version, timestamps and count/wait shapes, projects only the canonical fields, then uses the existing immutable shard write and exact readback. No provider request occurs in the helper.
- A single primary batch advances the pointer, inserts a stable `a4-overflow-v1:<digest>` run, updates that source's existing LIVE health record, and asserts exact evidence before commit. Each SQL evidence write checks exact pointer identity (terminal, UTC observation, digest, cardinality) inside the batch, and health also checks the exact successful run. No statement depends on cross-statement changes(). A stale run, same observation time or newer legacy health/run cannot regress evidence. Run columns and source-specific records-read (T1 accepted terminal, T2 normalized row count) preserve existing conventions. Records-written here counts logical published observations, not billed D1 index or statement writes. Health retains original observation/retrieval clock, schema, failure reset and prior published clock. A swallowed/no-op evidence write is tested to roll back the pointer and run.
- A timeout can leave an immutable orphan, never a visible partially published capture. Re-try storage with the exact same rows, order-independent canonical payload, run start and finish, and original status, not another provider call. A suppressed equal/stale generation is not a new success or a source-health rewrite. Keep the old writer and readers untouched until staging. Keep one writer per terminal when enabling the completed design; the generic reference fixture adapter is not an alternate deployment writer.
- Worker binding semantics are tested against Miniflare D1 using the repository's actual primary table DDL and two independent local databases. This proves local transaction rollback, not remote REST atomicity or production run-time quotas. A staged REST D1 batch must reproduce the same assertions and lost-ACK readback with real metadata before remote use. Reader, range diagnostics, source measurement and operational CAS must use the same immutable generation proof; no current code here can declare an incident healthy from sharded data.
- The prototype persists one at-most-48KiB manifest, one pointer upsert, one legacy-shaped run/health pair, and one bounded assertion per successful generation; no duplicate raw writes. Measure exact staging bytes, metadata and retention independently. Same-time corrections/partial and mixed-observation-time responses need parity verification against real approved captures before routing. Do not infer savings or retire any primary retention path from this test.
