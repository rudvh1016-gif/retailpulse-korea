# 서울 업종 실행 가이드 — Blender 장면과 접히는 설명

기준 main: `565c0341cfd2cea1ff9d2eaccdd68283f7179701`.

실서비스 `/ko/business`에서 서울 업종 가이드에 그림이 없고 긴 실행 설명이 모두 펼쳐져 있음을 Chromium으로 확인했다. 서울 가이드에 업종 그림·운영 초점·기존 세 가지 제목을 연결하고 실행 방법, 주의점, 마감 기록을 기본으로 접는다. 문구는 기존 4개 언어 운영 제안 그대로다. 공항 가이드는 기존 이미지와 펼쳐진 실행 설명, 매장 위치 선택을 유지한다.

## 장면과 재사용

- 기존 승인된 8개 매장 WebP를 실제 픽셀로 확인했다. 패션, 카페, 팝업, 관광·숙박, 주류·담배, 명품은 기존 장면을 재사용한다.
- 뷰티는 미용실 좌석 중심인 기존 그림을 대신해 색조 테스터, 일회용 도구, 기초제품 진열, 거울 상담대, 선물 포장·계산대를 Blender로 구성했다. 로즈와 브러시드 브라스 소재를 사용한다.
- 편의·약국은 의약품 상자와 상담대, 작은 약국 표식, 분리된 냉장 음료 진열과 바코드 계산대·장바구니로 두 업종의 업무를 구별한다. 민트와 세이지 소재를 사용한다.
- 새 장면에는 텍스트·수치·날씨·행사·실제 매장 위치를 넣지 않았다. 그림은 운영 공간 예시임을 HTML 캡션으로 밝힌다.
- Blender 5.2.1 LTS, Cycles 64 samples, AgX. 재현 명령: `blender --background --factory-startup --python scripts/render-industry-scenes.py`.
- 편집 가능한 두 `.blend`와 생성 스크립트: `docs/assets/industry-guide-v1-blender.zip`. 원본 스크립트는 `scripts/render-industry-scenes.py`.
- 렌더 바이트 수와 SHA-256: `config/industry-scenes-v1.json`. 기존 승인 이미지와 공항 자산은 교체하지 않았다.

## 표시와 접근성

기존 Pretendard 및 다국어 글꼴, 제목·본문 크기를 유지한다. 서울 가이드 제목과 선택 밑줄, 설명은 검정이다. 기본 HTML `details/summary`로 터치·키보드에서 설명을 열고 닫으며 업종을 바꾸면 상세 설명이 접힌다. 모든 기존 설명은 DOM에 유지된다. 이미지의 정보는 인접한 제목과 운영 안내로 제공하므로 이미지는 장식용 빈 alt를 사용한다.

새 WebP는 투명 배경 4:3이며 480×360 / 960×720 두 크기다. `srcset`, `sizes`, 명시적 width/height, `loading="lazy"`, `decoding="async"`를 사용한다. 선택한 장면만 렌더링하며 런타임 3D, 라이브러리, 글꼴, 수집·API·D1 쓰기를 추가하지 않는다. 뷰티 960px 35,888 bytes / 480px 13,850 bytes, 편의약국 960px 29,196 bytes / 480px 11,506 bytes.

## 검증 근거

- 업종 가이드 Chromium E2E 12/12: 4개 언어 × 390/1280px, 8개 업종의 모든 기존 설명·주의점, 공항 위치 선택, 자료 누락, 320/390/430px 키보드 펼침과 이미지 로딩·검정 제목·넘침 검증.
- 실제 공개 summary `generatedAt=2026-10-06T09:27:06.677Z`를 로컬 앱에 읽기 전용으로 공급해 뷰티·편의약국 × 320/390/430px 최종 캡처 6장을 저장했다. 숫자와 기준시각은 응답 그대로이며 이 snapshot은 제품 코드에 포함하지 않았다. 페이지 오류와 가로 넘침은 없었다.
- 검증 빌드: 저장소의 `scripts/build-verified.sh` 성공.
- 타입 검사 성공, 전체 린트 오류 0 / 기존 이미지 경고 7, 렌더된 HTML 42/42 PASS. 전체 작업트리와 접근 가능한 Git 이력의 비밀정보 검사 성공.
- 전체 단위 검사 최초 정상 사용자 실행: 1,163건 중 1,162 PASS, 1건은 Windows CRLF 체크아웃에서 workflow 문자열 검사 실패. 저장소 HEAD의 원본 LF 바이트를 복원한 뒤 해당 파일과 Owner UI Lock을 재검사해 59/59 PASS. 보호 기준 fixture와 모든 보호 파일은 Git HEAD와 동일하다.
- 샌드박스의 최초 단위 검사 실행은 `uv_os_get_passwd returned ENOMEM`으로 실패했다. 계정 조회가 가능한 정상 사용자 실행으로 위 검증을 수행했다.
- 물리 휴대전화와 Safari는 이 변경에서 확인하지 않았다. 원격 CI는 정확한 PR head에서 별도로 확인한다.

참고 첨부 Library 3개는 정식 가져오기 준비는 성공했지만 Windows 전송 helper가 `AttributeError: module 'os' has no attribute 'setxattr'`로 실패했다. 해당 첨부의 픽셀 비교를 했다고 주장하지 않는다. 실서비스 화면, 현재 코드, 기존 저장소 자산의 픽셀 확인으로 작업했다.
