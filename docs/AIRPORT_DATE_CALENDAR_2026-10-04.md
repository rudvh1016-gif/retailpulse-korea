# Airport date calendar

The airport's three yesterday/today/tomorrow choices keep their existing server-KST semantics. The native date field is replaced by a white rounded trigger with readable `Intl.DateTimeFormat` date text and a decorative Blender calendar icon. The calendar is a native modal dialog, shown as a bottom sheet on mobile and a positioned popover on desktop. Other area date controls retain their existing native implementation in this independent unit.

Dates remain HTML buttons/text. Enter/Space activates dates, arrows move focus by day/week across months, month controls allow older and future dates, Escape/back dismiss without choosing, and selection restores trigger focus. Browser history uses a temporary same-URL entry while open. The existing selected-date URL, server clock/midnight logic, stored dates, source scopes and last-good protections remain. The old unbounded native picker allowed dates outside stored data; this remains intentional. Dots describe the union of actually held flight/forecast/schedule dates for the requested month, with loading/failure wording; absence of a dot does not claim data is impossible. No provider request per date, new API, dependency, account or personal-data persistence is added.

The supplied `date_calendar_icon_v1` assets were verified locally and the actual pixels inspected. The three 32px WebPs are 1,368 / 3,206 / 5,276 bytes, selected through 1x/2x/3x `srcSet`; image width/height reserve 32px. Source ZIP: `libfile_bed2e809edb4819188f0c7a0b5e2baa4`; source manifest: `libfile_e2127ae105d08191a3ef473f4bed0478`. They were made in Blender 5.2.1 LTS with transparent background and no baked dates, numbers, fonts or logo. No runtime 3D engine. The earlier WIP icon remains preserved and unreferenced. Original source `.blend` stays in the producer folder and source ZIP.

The owner's explicit redesign request authorizes the limited live-signals/app integration recorded in the active `ownerModernCalendar20261004` lock transition. No lock test is skipped or disabled.
