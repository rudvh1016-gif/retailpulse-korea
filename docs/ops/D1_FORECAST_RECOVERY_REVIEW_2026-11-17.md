Turning READS off restores original read routing; keeping active DATABASE_ID while WRITES=false pauses that family with zero provider requests and prevents fallback to the full original. Never remove that identity as the pause operation. An older Worker with the original DB binding sees exactly the preserved original records but cannot see new active-only publications. Local tests execute frozen base `4ade5ed` summary logic against the same read-only archive and compare disabled output; they do not constitute an actual old Cloudflare Worker rollback deployment or CPU proof.

## Critical admission limitation: production HOLD

The existing family mutexes remain: production-collector-forecast for primary/recovery A5, production-collector-weather for weather, and the realtime cycle's existing serialization. DB capacity latches do not block another family's database. Existing annotations provide transition notices, not a new external channel. Capacity error 7500+maximum-size is permanent; UNIQUE 7500 is not mistaken for capacity.

Cold missing/corrupt admission files fail before SQL/provider requests. Bootstrap now requires the corresponding flag, an ISO expiry at most 15 minutes away, and an exact 40-character approved commit equal to GITHUB_SHA. Each family has its own database identity and state file/cache namespace; default bootstrap is false.

However, Actions cache is NOT an authoritative durable fence. Reproduced counterexample: an older valid unblocked cache exists; a later run hits capacity and saves blocked state locally; cache save fails or the run aborts; next run restores the older valid cache and loses the block. Mutexes and cache-miss checks do not detect that rollback. Notices can also repeat after lost cache. Thus automatic repeated production collection is HOLD until an independently authoritative monotonic generation/fencing or latest-state attestation is implemented and verified, outside the full database. Do not claim exactly-once or durable duplicate suppression. No such new external control, permission or credential was configured here. A cache epoch is not proof of latest state. A capacity block must not be cleared automatically.
