# GA4 방문 해석과 운영 검사 구분 검토

기준: `origin/main` 7d99392ed8679943809ad278ecdd01a630cf87fa. 이 문서는 초안이며 GA 설정, 배포 또는 필터 활성화를 수행하지 않는다. 속성 553077650은 한국 시간대다.

## 수치의 의미

| 한국 시간 | 10/14–20 | 10/21–27 | 변화 |
| --- | ---: | ---: | ---: |
| 신규 사용자 | 84 | 37 | -47, 약 -56.0% |
| 활성 사용자 | 85 | 42 | -43, 약 -50.6% |
| 조회수 | 462 | 535 | +73, 약 +15.8% |
| 재방문 사용자 | 미확인 | 미확인 | 미확인 |
| 세션 | 같은 기간 값 미확인 | 같은 기간 값 미확인 | 미확인 |

신규 사용자는 첫 방문 이벤트 기준, 재방문 사용자는 이전 세션을 시작한 적이 있는 사용자, 활성 사용자는 GA의 참여 기준에 해당하는 사용자다. 활성에는 첫 방문 등도 포함될 수 있으므로 '관심 있게 적극적으로 읽은 사람'과 동일하지 않다. 조회수는 페이지 조회 횟수이고 세션은 방문 기간의 수다. 같은 사람이 여러 세션·조회수를 만들 수 있다. 신규·재방문은 해당 기간에 겹칠 수 있고 활성 사용자에서 신규를 빼 재방문자를 구하지 않는다. 브라우저·쿠키, 동의 설정과 자동 검사 영향 때문에 사람 수와 일치하지 않는다. 두 기간의 활성 사용자 감소는 **측정된 활성 사용자 수 감소**이며 실제 독자의 감소 규모나 원인을 단정하지 않는다.

별도로 전달받은 최근 7일 세션 150 중 Direct 148, Unassigned 2는 위 표의 기간과 반드시 같다고 가정하지 않는다. Direct는 출처가 확인되지 않은 경우도 포함하며, Unassigned는 GA 채널 규칙에 분류되지 않은 경우다. 코드가 `page_referrer`를 빈 값으로 설정하고 `page_location`의 쿼리를 없애기 때문에 검색·외부 링크 및 캠페인 정보가 빠질 수 있다. 따라서 148을 주소 직접 입력이나 북마크로 해석하지 않는다. 누락된 과거 출처와 표식 없는 과거 운영자 방문은 정확히 복원할 수 없다.

## 현재 구현과 범위

- `app/page-analytics.tsx`가 설정을 읽은 뒤 경로별 수동 조회를 기록한다. `send_page_view:false`, 같은 경로 재렌더 중복 방지, 허용된 경로만 전송 및 쿼리·해시·referrer 제거를 확인했다. 실제 운영 스트림의 향상된 측정 상태와 중복 부재는 현재 별도 검증이 필요하다. 향상된 측정이 자동 이력을 보낼 수 있으므로 임의로 켜지 않는다.
- 운영자 본인의 브라우저는 더보기의 선택적 이용 통계를 끄면 이후 전송이 중단된다. 이미 보낸 데이터는 지워지지 않고 각 브라우저·기기에서 따로 설정해야 한다.
- 운영 Playwright 설정은 선택적 통계를 끈 저장 상태와 Chromium Google 호스트 차단을 사용한다. 기본값을 검사하는 테스트는 요청도 차단한다. GA 브라우저 프로브는 기본적으로 수집 요청을 차단하지만 명시적인 `deliver_test_hit`는 실제 표식 방문을 전송한다. 외부 도구나 이 설정을 쓰지 않는 자동 브라우저까지 보장하지 않는다.
- 기존 Internal Traffic 제외 필터는 **테스트**로 전달받았다. 테스트는 데이터 삭제가 아니라 일치 이벤트를 `Test data filter name`으로 표시한다. 필터의 실제 `traffic_type` 조건과 태그 내부 트래픽 규칙은 아직 확인되지 않았다. 개발자 트래픽 필터는 없다.

## 운영자 탭 표식 초안

이 변경은 분석이 허용된 경우에만 해당 탭의 `sessionStorage` 값이 정확히 `true`일 때 Google tag 설정에 고정값 `traffic_type=internal`을 넣는다. 이름·IP·계정·자유 입력은 추가하지 않는다. 새 탭, 다른 기기, 저장 차단, 기존에 초기화된 페이지와 표식을 켜기 전 이벤트에는 적용을 보장하지 않는다. 새 탭은 브라우저에 따라 기존 탭의 세션 저장소를 복사할 수 있으므로 각 탭에서 확인한다. 표식은 사용자 인증이 아니며 누구나 바꿀 수 있다. 일반 방문자가 이를 설정하지 않으면 기존 전송과 같다.

배포가 별도 승인되고 테스트 필터가 `internal`에 일치함을 확인한 후, 이미 통계를 꺼 둔 운영자 탭에서 브라우저 개발자 도구 콘솔에 `sessionStorage.setItem('koretail-analytics-operator-v1', 'true')`를 실행하고 **통계를 끈 상태에서 페이지를 새로고침**한다. 그 다음 더보기에서 통계를 켜면 초기 설정에 표식이 포함된다. 새로고침 없이 켜면 이미 초기화된 태그에 표식이 반영되지 않을 수 있다. 표식을 없애려면 통계를 먼저 끄고 `sessionStorage.removeItem('koretail-analytics-operator-v1')`를 실행한 뒤 페이지를 새로고침한다. 작업 방문을 아예 보내지 않으려면 통계를 계속 꺼 둔다. 전환 전 이미 시작된 세션이나 이전 이벤트는 소급 수정되지 않는다.

테스트 필터가 그대로 테스트인지, 조건이 `internal`인지 먼저 확인한다. 통계가 꺼진 대조 탭과 표식 탭을 각각 검사하고, 프로브로 실제 전송 파라미터 및 첫 조회·이후 조회·허용 이벤트를 확인한다. GA 탐색에서 `Test data filter name`, `Event name`, `Event count`를 비교하고 해당 필터 이름의 표시를 확인한다. 처리에 24–36시간이 걸릴 수 있다. 자동 생성되는 first_visit/session_start/user_engagement와 세션·사용자 집계에서의 적용은 실제 수신 검증 전 미확정이다. 이벤트 표식이 세션이나 사용자 전체를 완벽하게 분리한다고 가정하거나 이벤트 수를 사용자 수에서 빼지 않는다.

**활성 제외 필터는 승인 전 금지:** 일치하는 새 데이터가 영구적으로 처리·보고에서 제외된다. 조건, 다른 공유 IP 또는 표시 오류에 따른 일반 방문 손실 가능성, 자동 생성 이벤트 적용 범위를 검증하고 부모에게 보고한 뒤 별도 승인을 받는다. 필터를 활성화하지 않아도 테스트 표식으로 탐색 비교는 가능하나 표식 없는 작업 방문은 구별되지 않는다.

## 출처 개선의 별도 검토

현행 개인정보 약속은 원문 referrer·검색어·쿼리를 보내지 않는다. 현재 제약을 유지한 채 출처를 개선하려면 브라우저에서 정해진 검색 엔진 호스트만 분류해 고정된 범주를 전송하고, 그 외 외부 referrer는 단일 범주로만 처리하는 방안을 별도 설계·검증할 수 있다. 전달되지 않은 referrer, 앱·브라우저 정책, 검색 도메인 변형, 캠페인 URL 손실과 세션 귀속 때문에 그마저도 완전한 출처 복원이 아니다. GA 기본 채널에 임의 매핑하면 오분류될 수 있으므로 이 PR은 그러한 전송이나 채널 변경을 하지 않는다. 기존 개인정보 고지 및 허용 목록을 검토하고 실제 수신과 보고 단위를 확인한 뒤 별도로 결정한다.

## 검증 기록

- 표식·동의·안전 경로·기존 자동 검사 차단 관련 단위 검사를 실행했다. Windows의 자동 CRLF 변환 때문에 기존 프로브 검사 1건이 처음 실패했으며, 해당 워크플로를 Git 원본 LF로 잠시 읽어 다시 실행해 12/12 통과했다. 워크플로 변경은 남기지 않았다.
- ESLint 변경 파일과 TypeScript 전체 검사 통과. 공항 정적 산출물 빌드 후 `vinext build` 직접 실행 성공. 표준 `npm run build`는 이 Windows 환경의 PATH에서 `bash`를 찾지 못해 중단됐다. 생성된 공항 파일 변경은 되돌렸다.
- Chrome에서 합성 페이지에 실제 분석 모듈을 번들링하여 표식 있는 탭과 없는 탭, 동의 전 무전송, 각 경로당 수동 조회를 확인했다. 모든 외부 요청을 차단하고 Google 태그는 실행하지 않았다. 이는 실제 사이트 전체 흐름이나 Google의 `traffic_type` 수신·처리를 검증한 것이 아니다.
- 전체 Git 이력 비밀 검사는 실행했으나 방대한 이력 때문에 완료 전 중단했다. 실제 GA 수신, 필터 일치, 향상된 측정 현황과 원격 CI는 미확정이다.
