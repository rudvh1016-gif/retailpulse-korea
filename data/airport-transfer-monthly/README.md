# 터미널 이전월 공식 월실적 보존

기준 main: `39b7852c32d9f304a26254492a18ae94da8d7e38` (PR #499 병합 상태).
독립 브랜치: `data/terminal-transfer-official-history`.

사용자가 요청한 에어부산 2025-07, 에어서울 2025-09, 아시아나 2026-01의
인천공항 여객기 월실적을 공식 공개 통계에서 확보했다. 항공사마다 T1, T2,
전체를 각각 조회하여 9건을 보존한다. 전체는 검산용이며 T1/T2에 더하지 않는다.

- 정규화 자료: `public/data/airport-transfer-monthly.json`
- 공식 출처: https://airinfo.airport.kr/fsmFsn/co_ko/statisticCategoryOfAirline.do?layout=636f5f6b6f40403635314040666e637431
- 조회 조건: 여객기, 정기/부정기 전체, 국제/국내 전체, 여객 구분 전체,
  해당 항공사, 시작/종료 동일 연월, 해당 터미널 또는 전체.
- 단위: 운항 편, 여객 명. 도착/출발/합계를 별도로 보존한다.
- 기간: KST 달력월 전체. 예정편이나 일별 관측이 아닌 공식 월 실적이다.
- 각 관측에 정확한 조회 URL, 응답 저장 완료 UTC 시각(`retrievedAt`),
  전체 응답 SHA-256, 증거 발췌 SHA-256, 발췌 경로를 보존한다.
  저장 완료 시각은 공식 발표 시각이 아니다.
- `raw/*.html.gz`는 공식 응답의 조회 조건 초기화 코드, 폼, 통계 표를
  그대로 발췌하여 gzip으로 압축한 증거다. 포털의 공통 메뉴·지도·추적 스크립트는
  자료와 무관하므로 제외했다. `fullResponseSha256`은 전체 응답의 해시이고,
  공개 증거 파일은 `evidenceSha256`으로 검증한다.
- 외부 HTML은 코드로 실행하지 않는다. 공식 표에 함께 있는 전체 합계와 전년
  증감률 행은 관측으로 중복 수집하지 않았다. 전체 조회의 화물 열도 제외한다.

## 검증

`node scripts/verify-airport-transfer-monthly.mjs`

9건의 증거 해시, 항공사/연월/여객기/터미널 선택값, 표 수치, 정수/비음수,
출발+도착=합계, 각 지표·방향에서 T1+T2=전체가 모두 통과했다.
조회 원자료에서 읽은 월 실적이며, 현재 API 결과를 과거자료로 저장하지 않았다.

## 전후 4주 비교의 누락 범위

| 항공사 / 이전일 | 이전 28일 | 이후 28일 | 필요한 인접 월 |
|---|---|---|---|
| 에어부산 / 2025-07-29 | 2025-07-01~07-28 | 2025-07-29~08-25 | 2025-07,08 |
| 에어서울 / 2025-09-09 | 2025-08-12~09-08 | 2025-09-09~10-06 | 2025-08,09,10 |
| 아시아나 / 2026-01-14 | 2025-12-17~2026-01-13 | 2026-01-14~02-10 | 2025-12,2026-01,02 |

현재 화면은 `airport_daily_composition`의 날짜별 `profile`을
`/api/live/airport-days`로 읽는다. `lib/airport-day-profile.ts`는 편별 ID로
공동운항을 중복 제거하고 취소편을 제외하여 터미널·시간·게이트 측면·목적지를
집계하며, 종료 후 스캔 근거가 있는 날만 complete로 인정한다.
위 월 실적 9건으로 날짜·시간·게이트·목적지나 취소편 정의를 복원할 수 없다.
필요한 168일의 일별 프로필 중 이번 작업이 확보/작성한 것은 **0일**이다.
기존 운영 DB의 해당 기간 실제 행 수는 인증된 읽기를 수행하지 않아 미확인이다.

상세운항 공식 API 설명 https://www.data.go.kr/data/15140153/openapi.do 는
부모 조사에서 D-3~D+6 제공으로 확인되었다. 따라서 현재 API 호출로 이 과거
기간을 소급 확보할 수 없다. 월통계 페이지의 일별통계 메뉴가 가리키는
`statisticCategoryOfairline.do`(소문자 a)는 조사 시 공식 '페이지를 찾을 수 없습니다'
응답이었다. 이것은 모든 공식 일별자료가 존재하지 않는다는 증명이 아니다.
요청한 과거 기간의 편별/터미널/시간/게이트/목적지 자료의 공개 경로는 아직 확보하지 못했다.
월총계를 균등 분배하거나 가짜 편별 ID·완료 스캔을 생성해서는 안 된다.

## 저장 경계와 이어서 할 일

기존 `airport_monthly_stats`는 `drizzle/0027` CHECK 제약에서
`ROUTE_COUNTRY_PASSENGERS`와 `TIME_BAND_PASSENGERS`만 허용한다.
새 자료는 항공사·터미널 차원이므로 그 테이블이나 일별 프로필에 넣지 않았다.
스키마·수집기·스케줄·UI·운영 D1 행은 변경하지 않았다.

이 PR은 저장소의 별도 정적 JSON과 원문 증거 보존이다. 병합·배포 시 정규화
자료는 기존 public 정적 자산 방식으로 `/data/airport-transfer-monthly.json`에서
제공할 수 있다. 현재 비교 화면에 연결하지 않았고 운영 사이트 반영도 미완료다.
UI PR #498, 분석 PR #497, 휴일 PR #501과 배포 순서를 부모 작업방에서 조율한다.
추가 권한·API키·유료서비스·보안설정 변경은 요청하거나 실행하지 않았다.

공식 이전 근거(부모 확인):
- 에어부산: https://www.airbusan.com/content/common/introduction/newsDetail?id=1906
- 에어서울: https://flyairseoul.com/CM/ko/noticeContent.do?board_id=notice&seq=9726
- 아시아나: https://flyasiana.com/C/KR/KO/customer/notice/detail?id=CM202509300002526502

추가 월실적이 필요하면 위 조건으로 인접 월을 **월별 별도 자료**로 확보할 수
있으나, 그 자료 역시 4주 비교의 일별 프로필을 대체하지 못한다.
